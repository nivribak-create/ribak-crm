## מה יש בפנים

- **לוח בקרה** – KPI-ים, משפך עם דליפות לכל שלב (המשיכו / עדיין בשלב / אבדו), סיבות אובדן, לידים לפי שבוע, המרה לפי מקור, זמן חציוני בין שלבים, ניסיונות ללא מענה, ורשימת "לחזור אליהם היום". סינון לפי טווח (7/30/90 ימים/הכל) ולפי מקור. הניתוח הוא לפי קוהורטה – תאריך כניסת הליד.
- **פייפליין** – לוח קנבן לפי שלבים, כרטיס לכל ליד עם חיוג ווואטסאפ בלחיצה, פעולות "התקדם" / "לא ענה" / "אבד", וטור אבודים עם החזרה לפייפליין.
- **לידים** – טבלה עם חיפוש, סינון, מיון וייצוא CSV.
- **מיון מהיר** – גוררים קובץ אקסל/CSV של אנשי קשר, והמערכת מגישה אותם קלף‑קלף: לוחצים שלב (או 1–6 במקלדת), הקלף עף, הבא נכנס. יש ביטול, דילוג, זיהוי כפילויות מול הדאטהבייס, ותיוג מקור דביק בין קלפים. הקובץ נקרא בדפדפן בלבד ולא נשלח לשום מקום.
- **פרטי ליד** – היסטוריה מלאה (כל מעבר, ניסיון, אובדן והערה), פעולה הבאה, הערות.
- **נתונים** – גיבוי/ייבוא JSON, נתוני דוגמה, ערכת צבע בהירה/כהה.

## שני מצבי עבודה

| מצב | מתי | איפה הלידים |
|---|---|---|
| **משותף** (remote) | כשהאפליקציה רצה על `server.js` עם דאטהבייס | MySQL – משותף לכל מי שנכנס עם הסיסמה, מכל מכשיר |
| **מקומי** (local) | כשאין שרת (GitHub Pages, אחסון סטטי, פיתוח) | `localStorage` של הדפדפן – במכשיר הזה בלבד |

המצב נקבע אוטומטית בטעינה (`GET api/session`). במצב משותף מופיע מסך כניסה; בכניסה הראשונה ממכשיר שיש בו לידים מקומיים המערכת מציעה להעלות אותם לדאטהבייס.

## הרצה על Hostinger (Node.js Web App)

1. יוצרים אתר מסוג **Node.js** מהריפו הזה (ענף `main`). Hostinger מריץ `npm install` ואז `npm start`.
2. יוצרים דאטהבייס MySQL ב-hPanel (Databases → MySQL).
3. ב-**Environment variables** של האפליקציה מגדירים:

| משתנה | ערך |
|---|---|
| `DB_HOST` | ה-host של MySQL כפי שמופיע ב-hPanel |
| `DB_PORT` | `3306` (ברירת מחדל) |
| `DB_NAME` | שם הדאטהבייס |
| `DB_USER` | שם המשתמש |
| `DB_PASSWORD` | הסיסמה של המשתמש |
| `CRM_PASSWORD` | סיסמת הכניסה למערכת (משותפת) |
| `SESSION_SECRET` | לא חובה – מחרוזת אקראית לחתימת ה-cookie |
| `SESSION_DAYS` | לא חובה – כמה ימים כניסה נשמרת (ברירת מחדל 30) |
| `WEBHOOK_SECRET` | לא חובה – מפתח סודי שמפעיל את `POST /api/inbound/lead` לאוטומציות |

הטבלאות נוצרות לבד בהפעלה הראשונה. עד שההגדרות לא מלאות, האתר מציג מסך "השרת עוד לא מחובר" עם רשימת מה שחסר.

## הרצה מקומית

**ממשק בלבד (מצב מקומי):** כל שרת קבצים, למשל `python3 -m http.server 8765`, ואז `http://localhost:8765`.
(פתיחה ישירה של `index.html` מהדיסק לא תעבוד – הדפדפן חוסם ES modules מ-`file://`.)

**עם שרת ודאטהבייס:** `npm install`, להגדיר את משתני הסביבה שלמעלה, `npm start`, ואז `http://localhost:3000`.

## API

כל הנתיבים תחת `api/`, JSON. `/leads` ו-`/settings` דורשים כניסה (cookie חתום).

| | |
|---|---|
| `GET /session` | מצב השרת: מוגדר? דאטהבייס תקין? מחובר? |
| `POST /login` `{password}` · `POST /logout` | כניסה / יציאה |
| `GET /leads` | כל הלידים + הגדרות |
| `PUT /leads/:id` | שמירת ליד (יצירה או עדכון) |
| `DELETE /leads/:id` | מחיקת ליד |
| `PUT /leads` `{leads:[…]}` | החלפת כל הלידים (ייבוא, דוגמה, ניקוי) |
| `PUT /settings` | שמירת הגדרות |
| `POST /inbound/lead` | כניסת ליד מאוטומציה (ManyChat / Make / n8n). כותרת `X-Webhook-Key: <WEBHOOK_SECRET>`; גוף `{name, phone \| text, username, source, notes}` – המספר מחולץ גם מתוך הטקסט; ליד קיים עם אותו מספר מקבל הערה במקום כפילות |

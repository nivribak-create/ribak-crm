# Ribak CRM

באוויר: **https://blanchedalmond-yak-848858.hostingersite.com** (Hostinger Node.js + MySQL, נפרס אוטומטית מ-`main`)
גיבוי במצב מקומי: https://nivribak-create.github.io/ribak-crm/ (GitHub Pages)

מערכת ניהול לידים עם אנליטיקת המרה מלאה – מליד חדש ועד סגירת מנוי.
ממשק ב-HTML/CSS/JS ללא build, ושרת Node.js/Express קטן ששומר את הלידים ב-MySQL ומגן עליהם בסיסמה אחת משותפת. עובד בדפדפן ובטלפון (ניתן להתקין כאפליקציה במסך הבית).

בנוי סביב המקצב האמיתי של Ribak: הזמנות נסגרות **רביעי 23:00**, האוכל מגיע **ביום ראשון**, ושיחת ההמרה למנוי היא **ביום שלישי** – כלומר לליד שנסגר אחרי רביעי בלילה יש שבוע המתנה נוסף.

| ליד חדש | השאיר פנייה, עוד לא דיברנו | מספר לא תקין · לא רלוונטי · מחוץ לאזור |

**מכירה ושימור הן שתי שאלות נפרדות.** לקוח שסגר מנוי והפסיק נשאר ספור כמכירה מוצלחת במשפך, ומופיע בנפרד כנטישה. הפאנל "מה יצא מהלידים" מפצל את כולם לשש תוצאות – עדיין בטיפול · מנוי פעיל · היה מנוי והפסיק · הזמין שוב בלי מנוי · ניסה שבוע ולא המשיך · אבד לפני הניסיון – ולחיצה על שורה פותחת את הרשימה המסוננת.

שלוש סיבות – **מספר לא תקין**, **לא רלוונטי / כפילות** ו**מחוץ לאזור החלוקה** – מוציאות את הליד מחישוב אחוזי ההמרה, כי מלכתחילה לא היתה שם עסקה אפשרית. הן מסומנות ב-∅, ובחירה באחת מהן מציגה אזהרה לפני השמירה.

**לחיצה על "לא ענה" בליד חדש מעבירה אותו לפולואפ** – כך הלוח מפריד בין "עוד לא ניסינו" ל"ניסינו ולא תפסנו". וכל כרטיס שביצעת בו פעולה היום שוקע לתחתית הטור עם תגית "טופל היום", וכותרת הטור מציגה כמה עוד ממתינים – עובדים מלמעלה למטה עד שהטור נקי. ליד נשאר בשלב האמיתי שלו ומקבל תאריך חזרה + מונה ניסיונות, כך שרשימת "לחזור אליהם היום" חוצה את כל השלבים בלי לאבד את המידע איפה כל אחד באמת נמצא.

מקורות הלידים מפרידים בין **אינסטגרם ממומן** ל**אינסטגרם משפיען**, ולמשפיען נשמר שם – כדי שאפשר יהיה לראות איזה משפיען מביא מנויים ולא רק חשיפה.

## מה יש בפנים

- **לוח בקרה** – שלושה חלקים בלבד: **סיכום היום** (לידים חדשים · חיוגים · שיחות מלאות · סגירות, עם אתמול להשוואה), **שתי ההמרות** – מליד חדש לשבוע ניסיון, ומשבוע ניסיון למנוי (מתוך מי שקיבל בפועל את האוכל), ו**השבוע הזה** – מי ממתין להמרה לפני סגירת ההזמנות ברביעי 23:00. כל השאר (משפך, סיבות אובדן, מקורות, משפיענים) מקופל מתחת ל"עוד נתונים" – נאסף ומחושב כרגיל, פשוט לא מפריע.
- **פייפליין** – בסוף הלוח יש **פולואפ עתידי**: ליד שסומן לחזור אליו אחרי שבת הקרובה ממתין שם ולא מעמיס את הלוח. השלב שלו לא משתנה – זו רק תצוגה – וכשמגיע התאריך הוא חוזר לבד לטור שממנו הגיע. גרירה לשם מבקשת תאריך; גרירה חזרה מחזירה אותו לעבודה מיד. לכל כרטיס יש כפתור העברה שפותח רשימת שלבים – שתי לחיצות ובלי לחפש טור שמחוץ למסך; גם שלבי המסלול בכרטיס הליד לחיצים. ואפשר גם לגרור כרטיס בין טורים בכל כיוון (בעכבר – מיד; במגע – לחיצה ארוכה קצרה, כדי שגלילה לא תוציא כרטיסים). גרירה לטור האבודים פותחת את בחירת הסיבה. לוח קנבן לפי שלבים, כרטיס לכל ליד עם חיוג ווואטסאפ בלחיצה, פעולות "התקדם" / "לא ענה" / "אבד", וטור אבודים עם החזרה לפייפליין.
- **לידים** – טבלה עם חיפוש, סינון, מיון וייצוא CSV. ליד כל מספר טלפון – בכל מסך במערכת – יש כפתור העתקה, ובראש הטבלה כפתור שמעתיק את כל המספרים שהסינון מציג – מספר בשורה, מוכן להדבקה בכלי דיוור הוואטסאפ.
- **תסריט שיחת מכירה** – כל ליד שעוד לא שילם על שבוע ניסיון (חדש / נוצר קשר / בוצעה שיחה) עובר במסך מלא את ארבעת שלבי התסריט: ברכה, בירור צרכים, פרזנטציה וסגירה. המשפטים לאמירה מוצגים בגדול, ומתחת לכל שאלה יש שדה לתעד בו את התשובה. כל הקלדה נשמרת מיד, שאלות משתנות לפי תשובות קודמות, המטרה של הלקוח משתקפת אוטומטית בפרזנטציה, ועיר מחוץ לאזור החלוקה מסומנת מיד. בסוף בוחרים איך השיחה נגמרה והליד מתקדם לבד. מה שתועד מוצג בכרטיס הליד – כדי שבשיחת יום שלישי תדע מה המטרה שלו.
- **משפיענים** – פייפליין נפרד לשיתופי פעולה: מי שרוצים לפנות אליו, למי כבר פנינו, ומי בשיחות. כל כרטיס מציג כמה לידים, שבועות ניסיון ומנויים המשפיען הזה באמת הביא, לפי הלידים שתויגו בשם המשתמש שלו. הכפתור **"משוך מהלידים"** מאתר לידים שכתוב עליהם שת״פ / שיתוף פעולה / משפיען / ברטר / collab, ומעביר אותם לרשימה אחרי אישור – עם אפשרות להוציא אותם מהפייפליין. מי שכבר הועבר לא מוצע שוב, גם אם קיבל שם משתמש אחר (ההתאמה היא גם לפי טלפון). בכרטיס ליד בודד יש גם **"העבר למשפיענים"** – למקרה שמגלים את זה תוך כדי שיחה.
- **מיון מהיר** – גוררים קובץ אקסל/CSV של אנשי קשר, והמערכת מגישה אותם קלף‑קלף: לוחצים שלב (או 1–6 במקלדת), הקלף עף, הבא נכנס. יש ביטול, דילוג, זיהוי כפילויות מול הדאטהבייס, ותיוג מקור דביק בין קלפים. הקובץ נקרא בדפדפן בלבד ולא נשלח לשום מקום.
- **פרטי ליד** – היסטוריה מלאה (כל מעבר, ניסיון, אובדן והערה), פעולה הבאה, הערות.
- **נתונים** – גיבוי/ייבוא JSON, נתוני דוגמה, ערכת צבע בהירה/כהה.

## שני מצבי עבודה

| מצב | מתי | איפה הלידים |
|---|---|---|
| **משותף** (remote) | כשהאפליקציה רצה על `server.js` עם דאטהבייס | MySQL – משותף לכל מי שנכנס עם הסיסמה, מכל מכשיר |
| **מקומי** (local) | כשאין שרת (GitHub Pages, אחסון סטטי, פיתוח) | `localStorage` של הדפדפן – במכשיר הזה בלבד |

המצב נקבע אוטומטית בטעינה (`GET api/session`). במצב משותף מופיע מסך כניסה; בכניסה הראשונה ממכשיר שיש בו לידים מקומיים המערכת מציעה להעלות אותם לדאטהבייס.

## הרצה על Hostinger (Node.js Web App)

1. יוצרים אתר מסוג **Node.js** מהריפו הזה (ענף `main`). Hostinger מריץ `npm install` ואז `npm start`.
2. יוצרים דאטהבייס MySQL ב-hPanel (Databases → MySQL).
3. ב-**Environment variables** של האפליקציה מגדירים:

| משתנה | ערך |
|---|---|
| `DB_HOST` | ה-host של MySQL כפי שמופיע ב-hPanel |
| `DB_PORT` | `3306` (ברירת מחדל) |
| `DB_NAME` | שם הדאטהבייס |
| `DB_USER` | שם המשתמש |
| `DB_PASSWORD` | הסיסמה של המשתמש |
| `CRM_PASSWORD` | סיסמת הכניסה למערכת (משותפת) |
| `SESSION_SECRET` | לא חובה – מחרוזת אקראית לחתימת ה-cookie |
| `SESSION_DAYS` | לא חובה – כמה ימים כניסה נשמרת (ברירת מחדל 30) |
| `WEBHOOK_SECRET` | לא חובה – מפתח סודי שמפעיל את `POST /api/inbound/lead` לאוטומציות |

הטבלאות נוצרות לבד בהפעלה הראשונה. עד שההגדרות לא מלאות, האתר מציג מסך "השרת עוד לא מחובר" עם רשימת מה שחסר.

## הרצה מקומית

**ממשק בלבד (מצב מקומי):** כל שרת קבצים, למשל `python3 -m http.server 8765`, ואז `http://localhost:8765`.
(פתיחה ישירה של `index.html` מהדיסק לא תעבוד – הדפדפן חוסם ES modules מ-`file://`.)

**עם שרת ודאטהבייס:** `npm install`, להגדיר את משתני הסביבה שלמעלה, `npm start`, ואז `http://localhost:3000`.

## API

כל הנתיבים תחת `api/`, JSON. `/leads` ו-`/settings` דורשים כניסה (cookie חתום).

| | |
|---|---|
| `GET /session` | מצב השרת: מוגדר? דאטהבייס תקין? מחובר? |
| `POST /login` `{password}` · `POST /logout` | כניסה / יציאה |
| `GET /leads` | כל הלידים + הגדרות |
| `PUT /leads/:id` | שמירת ליד (יצירה או עדכון) |
| `DELETE /leads/:id` | מחיקת ליד |
| `PUT /leads` `{leads:[…]}` | החלפת כל הלידים (ייבוא, דוגמה, ניקוי) |
| `PUT /settings` | שמירת הגדרות |
| `POST /inbound/lead` | כניסת ליד מאוטומציה (ManyChat / Make / n8n). כותרת `X-Webhook-Key: <WEBHOOK_SECRET>`; גוף `{name, phone \| text, username, source, notes}` – המספר מחולץ גם מתוך הטקסט; ליד קיים עם אותו מספר מקבל הערה במקום כפילות |

## לידים מאינסטגרם אוטומטית (ManyChat)

כל הודעה פרטית באינסטגרם שיש בה מספר טלפון ישראלי נכנסת ל-CRM כליד חדש.

1. **Hostinger** → האתר → Environment variables → משתנה חדש `WEBHOOK_SECRET` עם מחרוזת רנדומלית → Save → Restart.
2. **ManyChat** (דרוש Pro בשביל External Request) → Automation → New Automation → טריגר Instagram → **Default Reply**.
3. צעד **Action → External Request**:
   - Method `POST`, URL `https://<האתר>/api/inbound/lead`
   - Header: `X-Webhook-Key` = אותו `WEBHOOK_SECRET`
   - Body (JSON): `{"text": "{{Last Text Input}}", "username": "{{Instagram Username}}", "name": "{{First Name}} {{Last Name}}"}`
4. Publish.

התשובות שהשרת מחזיר: `201` – נוצר ליד; `200 {reason:"no_phone"}` – הודעה בלי מספר, אין מה לעשות (לא שגיאה, כדי שאפשר להעביר *כל* הודעה);
`200 {created:false, id}` – המספר כבר קיים, נוספה הערה לליד; `401` – מפתח שגוי; `503` – `WEBHOOK_SECRET` לא מוגדר.

ה-`source` מתקבל רק אם הוא אחד מהמקורות שבאפליקציה, אחרת הליד נרשם כ"אינסטגרם – ממומן".
